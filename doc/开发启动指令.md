# 开发启动指令（粘贴给执行者）

> 用法：把本文件放在《技术方案-V1.md》**前面**一起发送。
> 每次开新会话都要重发这一段，否则模型会忘掉约束。

---

你要实现一个 Flutter 本地旅行相册 App。请先完整读一遍《技术方案-V1.md》，然后按以下规则工作。

## 一、优先级

1. **技术方案文档 > 你的通用最佳实践。**
   文档里明确规定的实现方式（尤其是"地图自绘，不接 SDK"），即使你认为有更好的方案，也**按文档做**。
   有异议时，写在交付说明的"分歧点"一节，不要擅自替换。

2. **不要发明文档没写的功能。**
   需要但没写的，做最小实现，注释标 `// TODO(未定义): ...`。

3. **不要照搬 `prototype/` 里的 HTML 结构。**
   那份原型只用于还原视觉与交互，数据层完全不是真实实现。

## 二、交付方式

**分阶段交付，不要一次性给全部代码。**

```
阶段 A：项目骨架 + 数据层（SQLite 表、迁移、DAO/Repository）+ 单元自测
阶段 B：行程列表 + 时间轴 + 大图（只读链路）
阶段 C：导入链路（选图 → EXIF → 去重 → 分组预览 → 落库）
阶段 D：地图 + 足迹 + 选片 + 信息修正
阶段 E：分享九宫格 + 删除/回收站
阶段 F：打包（APK 签名 / IPA 说明）
```

每阶段结束时，必须交付三样东西：

1. **改动文件清单**（相对路径）
2. **本阶段自测结果**：对照文档 §9 清单逐条写"通过 / 未通过 / 未覆盖"，不许只写"已完成"
3. **自行决定项**：文档没写、你自己定的地方，列出来

我看到这三样后确认，你再进入下一阶段。

## 三、阶段 A 开始前的三件事

在写任何业务代码之前，先回答：

1. 你打算用什么方式实现"照片去重"的哈希计算？在哪个 Isolate 里跑？
2. `MapCanvas` 的两种 scale（行程内 / 全世界）如何共用一套坐标投影？
3. `PhotoInfoSheet` 只有一个，两个入口（大图 / 补救页）如何保证状态同步？

这三题答对了，后面的架构就不会歪。答错的话，返工代价很大。

## 四、技术校验点（每阶段结束自查）

| 检查 | 命令 / 方式 | 期望 |
|---|---|---|
| 页面层没有裸弹层 | `grep -rn "showModalBottomSheet(" lib/features` | 0 结果 |
| 页面层没有裸绘图 | `grep -rn "CustomPaint(" lib/features` | 0 结果 |
| 没有绕过 Repository | `grep -rn "sqflite\|rawQuery" lib/features` | 0 结果 |
| 依赖未被擅自升级 | 对比 `pubspec.lock` | 版本与文档 §2.3 一致 |

## 五、遇到这些情况，停下来问我

- 文档自相矛盾
- 平台限制导致文档方案不可行（例如 `receive_sharing_intent` 在目标 Android 版本上的行为与预期不符）
- 需要新增文档未列出的依赖
- 需要新增权限

**不要自己绕过。** 停下来描述问题 + 你的两个备选方案 + 倾向哪个，我来定。
