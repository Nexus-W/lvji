# 页面规格 · 行程列表（卡片 / 列表双视图）

> 对象：`/trips`（原型 `trips.html`）
> 本文档分两部分：**§1–§3 设计思路**（为什么这么做），**§4–§9 实现规格**（照着做）。
> 所有尺寸为 dp，基准屏 390×844。颜色取《技术方案-V1.md》§7。

---

## 1. 这一页要解决什么

用户打开 App，看到的是"我去过哪些地方"。

**核心矛盾**：两种使用状态，需求完全相反。

| 状态 | 用户想要 | 合适的形式 |
|---|---|---|
| 回顾 | 看图、看感觉、随便翻翻 | 大图卡片 |
| 查找 | "去年国庆那次是哪一趟" | 密集列表 |

如果只做卡片：行程一多（8 个以上），一屏只能看 1.5 张，找东西要一直滑。
如果只做列表：全是字，失去了"相册"的气质，用户不想点。

**结论：同一份数据，两种排布，一键切换，记住选择。**

> 这不是"两种设计风格"，是**两种任务**。切换按钮不是装饰，是任务切换开关。

## 2. 三个关键设计决策

### 2.1 为什么不用"左右滑动的卡片轮播"

轮播适合**少量、同类**的内容（比如 3 个推荐位）。
行程是**会增长的、需要查找的**集合 —— 轮播到第 8 张就没人愿意滑了，而且无法一眼比较。

**列表必须能纵向扫视。** 所以两种视图都是纵向排列，切换只改**每行的信息密度**。

### 2.2 封面为什么是「1 大 + 2 小」而不是一张大图

卡片封面区总高只有 80dp。如果放一张 16:9 大图：
- 80dp 高的图，宽度撑满 → 会被裁成一条，看不出是什么
- 只能传达"一张照片"

改成 **1.7 : 1 的分栏**（左边主图，右边两张上下叠）：

```
┌───────────────┬──────┐
│               │  副1 │
│     主图       ├──────┤
│               │  副2 │
└───────────────┴──────┘
   1.7fr          1fr
```

- 传达"这次旅行有很多照片"，而不是"一张封面"
- 三张图都是**裁切显示**（`cover`），不裁的话 80dp 里什么都看不清
- 三张图来自用户亲手挑选的封面 + 最近三次的封面历史，不是随机

### 2.3 切换按钮的图标，显示的是"点了会变成什么"

这是最容易被做反的一处：

```
当前 = 卡片视图  →  按钮显示「列表」图标（点了变列表）
当前 = 列表视图  →  按钮显示「网格」图标（点了变卡片）
```

如果反过来（显示当前状态），用户会以为是"当前位置指示"，不会去点。

> 同理适用于所有"切换型"按钮。判断标准：**图标描述目的地，不描述当前位置。**

## 3. 两种视图的信息取舍

同一份数据，两个视图**显示的信息不一样**，这是有意的：

| 信息 | 卡片视图 | 列表视图 | 理由 |
|---|---|---|---|
| 三张封面图 | ✅ 1 大 2 小 | ❌ 只 1 张 60×60 | 卡片看图，列表看字 |
| 行程名 | ✅ 14sp w600 | ✅ 13sp w600 | — |
| 张数 | ✅ 右上 | ✅ 右上 | — |
| 缺位置红点 | ✅ | ✅ | 必须两处都有 |
| `+N` 导入标记 | ✅ | ✅ | — |
| 日期 · 天数 | ✅ 一行（含天气条） | ✅ 一行 | 卡片放天气，列表不放 |
| 手记首行 | ✅ 单独一行，可点 | ✅ 第三行，不可点 | 见 §6.3 |
| 天气条 | ✅ | ❌ | 卡片有空间，列表要省 |

**原则**：卡片视图优先"氛围"，列表视图优先"识别"。列表里删掉天气，是因为一行塞不下，且天气对"找行程"没帮助。

## 5. 卡片视图规格

### 5.1 卡片盒

```
┌──────────────────────────────┐  ← 圆角 15，边框 1px #232C39
│ ┌──────────────────┬───────┐ │
│ │                  │ 副 1  │ │  ← 封面区 80dp
│ │      主图         ├───────┤ │
│ │                  │ 副 2  │ │
│ └──────────────────┴───────┘ │
│ 云南 · 大理丽江            842 张 │  ← 标题行
│ ☀ 18°  ☁ 16°  🌧 14°  ▾     │  ← 天气条
│ 风大得能把人吹下山          › │  ← 手记行
└──────────────────────────────┘
```

| 项 | 值 |
|---|---|
| 宽度 | 屏宽 − 32 |
| 圆角 | 15 |
| 背景 | `#0F141B` |
| 边框 | 1px `#232C39` |
| 按下态 | 边框变 `rgba(61,220,151,.35)` |
| 底部外边距 | 12 |

### 5.2 封面区

| 项 | 值 |
|---|---|
| 高 | 80 |
| 布局 | `grid-template-columns: 1.7fr 1fr`，`gap: 2` |
| 右侧 | 上下两格，`grid-template-rows: 1fr 1fr`，`gap: 2` |
| 图片填充 | `cover`（裁切，不拉伸） |
| 间隙色 | `#0A0F14` |

**三张图的取法**（优先级从高到低）：

```
① 用户手动设过的封面（最近三次，按时间倒序）
② 行程的默认封面（第一张照片的场景）
③ 不足三张时重复用第一张，不要留空
```

### 5.3 信息区

内边距：上下 `6 / 10`，左右 `12`。

| 元素 | 字号 | 颜色 | 说明 |
|---|---|---|---|
| 行程名 | 14 w600 | #E9EEF6 | 单行，超出省略 |
| 缺位置红点 | 6×6 圆点 | #D9C48A | 紧跟名字，`gap 6` |
| 张数 | 9 | #65707F | 右对齐（`margin-left: auto`） |
| `+N` 标记 | 9 | #3DDC97 | 紧跟张数，左距 3 |
| 天气条 | 9 | #65707F | 距标题 6，图标 11×11，最多 7 天 |
| 手记行 | 12 | #9AA6B6 | 距天气 5，右侧 `›` 14sp |

**天气条**（一行两段）：

```
02☀  03☁  04🌧  05☀  06☁          2026.10.02 · 5 天
└──────── 最多 7 天 ────────┘        └── 右对齐 ——┘
```

| 段 | 内容 | 规格 |
|---|---|---|
| 左 | 每天：**日号后两位**（`02`）+ 天气图标 | 每项 `gap 3`，项间距 12；图标 11×11，`stroke #9AA6B6`，线宽 1.7 |
| 右 | 日期范围前 7 字 + `· N 天` | 9sp `#65707F`，`margin-left: auto` |

- 天数超过 7 天时，只显示前 7 天，**不加省略号**（第 8 天的图标会把右侧日期挤掉）。
- 若行程没有任何天气数据，**整行隐藏**，不留空行。

> 天气不是实时数据，是导入时按拍摄日期生成的示意。V1 不接天气 API。

### 5.4 点击热区（重要）

一张卡片里有两个**不同的**跳转：

| 热区 | 覆盖范围 | 目标 |
|---|---|---|
| 整卡（透明层 `.hit`） | 卡片全部区域，`z-index: 1` | **地图页** `/trip/:id/map` |
| 手记行（`.qrow`） | 只有手记那一行，`z-index: 2` | 时间轴 `/trip/:id` |

也就是说：**点卡片任意位置进地图，"点手记那一行进详情"**。

> 这是有意的：用户点行程，第一诉求是"看图在哪儿"。想看文字，点手记那行。
> 如果实现时把整卡都指向详情，地图就少了一个入口。

## 6. 列表视图规格

### 6.1 行盒

```
┌────────────────────────────────────────┐
│ ┌────┐  云南 · 大理丽江          842 张 │
│ │60× │  2026.10.02 - 10.06 · 5 天     │
│ │ 60 │  风大得能把人吹下山              │
│ └────┘                                  │
└────────────────────────────────────────┘
```

| 项 | 值 |
|---|---|
| 高 | 约 76（由内容撑开） |
| 内边距 | 8 |
| 圆角 | 12 |
| 背景 | `#151E27` |
| 间距 | 8 |
| 缩略图 | 60×60，圆角 8，`cover` |
| 内容间距 | 10 |

### 6.2 文字三行

| 行 | 字号 | 颜色 | 内容 |
|---|---|---|---|
| 1 | 13 w600 | #E9EEF6 | 行程名 + 红点，右端张数（9sp #65707F） |
| 2 | 9 | #65707F | `日期 · N 天` |
| 3 | 12 | #9AA6B6 | 手记首行，没有则「还没写手记」且透明度 65% |

### 6.3 为什么列表里手记不可点

列表行整块点击进地图。
如果手记那行再单独响应，一行 76dp 里就有两个热区，误触率高（拇指按下去经常压到边界）。

**规则：一行只给一个跳转。** 想看详情，从地图页顶部进入，或切回卡片视图点手记。

## 7. 切换交互

### 7.1 触发

点击头部右侧的视图按钮：`card ⇄ row`。

### 7.2 动画时序（总时长 420ms）

```
① 0ms    列表整体淡出 + 下移 6dp        120ms  ease
② 120ms  替换 DOM / 重建列表
③ 120ms  每一项淡入 + 上移 8dp          300ms  cubic-bezier(.22,1,.36,1)
         第 1~6 项依次延迟 0 / 30 / 60 / 90 / 120 / 150ms
         第 7 项以后不再延迟（避免长列表最后几张等太久）
④ 420ms  结束
```

- 首次进入页面**不做动画**（直接渲染）。
- 系统开启「减少动态效果」时，跳过所有动画，直接替换。

### 7.3 状态保持

| 项 | 是否保持 | 说明 |
|---|---|---|
| 视图模式 | ✅ | 存 `preferences: tripnest.view`，默认 `card` |
| 滚动位置 | ❌ 不保持 | 两种视图行高差异大，保持位置会跳到奇怪的地方。切换后滚回顶部 |
| 选中的行程 | — | 本页无选中态 |

### 7.4 按钮状态

- 点击时无 loading（切换是纯本地操作，瞬时完成）
- 连续快速点击：允许，但要做 150ms 节流，避免动画打架
- 按钮本身不显示"当前视图"文字

## 8. 特殊状态

### 8.1 空列表

```
        ┌──────────┐
        │   （图标） │
        │ 还没有行程  │
        │ 点右上角 ＋  │
        └──────────┘
```

居中，距顶 120。标题 14 w600，说明 11 #65707F。

### 8.2 卡片上的三个标记

| 标记 | 位置 | 含义 | 触发条件 |
|---|---|---|---|
| 红点 6×6 #D9C48A | 紧跟行程名 | 有照片缺位置 | `missing > 0` |
| `+N` 9sp #3DDC97 | 张数后 | 本次新增导入 N 张 | `imported > 0` |
| 手记行灰字 | 卡片底部 | 没写过手记 | `journal == ''` |

> 三个标记在两种视图里**都要显示**，不能只在卡片里有。

### 8.3 数据为空但行程存在

新行程没有照片：封面用占位（深色渐变 + 一个相机轮廓），张数显示 `0 张`，不要隐藏数字。

## 9. 实现要点（Flutter 对应）

### 9.1 结构

```dart
// 一个页面，两个 builder
Widget build(BuildContext context) {
  return Scaffold(
    body: Column(
      children: [
        _Header(view: view, onToggle: _toggle),
        Expanded(
          child: AnimatedSwitcher(
            duration: const Duration(milliseconds: 420),
            child: view == TripView.card
                ? _CardList(key: const ValueKey('card'), trips: trips)
                : _RowList(key: const ValueKey('row'), trips: trips),
          ),
        ),
      ],
    ),
  );
}
```

### 9.2 关键实现点

| 点 | 做法 |
|---|---|
| 视图持久化 | `SharedPreferences`，key `tripnest.view`，值 `card` / `row` |
| 切换后回顶 | `scrollController.jumpTo(0)` 放在动画**开始前**（放在结束后会看到跳动） |
| 三图封面 | `GridView` 或 `Row + Column`，全部 `BoxFit.cover` |
| 卡片双热区 | 整卡 `InkWell` + 手记行 `GestureDetector`（后者需 `behavior: opaque` 并置于上层） |
| 缩略图解码 | `cacheWidth: 180`（60dp × 3 倍屏），否则大图 OOM |
| 列表复用 | `ListView.builder`，**不要**一次 build 全部 |
| 减少动态 | 读 `MediaQuery.disableAnimations`，为 true 时 duration 设 `Duration.zero` |

### 9.3 数据来源（一张卡片需要什么）

```dart
class TripCardVM {
  final String id;
  final String name;
  final String range;        // '2026.10.02 - 10.06'
  final int days;
  final int photoCount;      // COUNT(*) where deleted_at is null
  final int missingCount;    // lat/lng 为 null 的张数
  final int importedCount;   // 本次新增（可空）
  final List<String> covers; // 最多 3 个缩略图 uri，不足补足
  final String journalFirstLine;
  final List<Weather> weather; // 最多 3 个，可空
}
```

> `photoCount` 必须来自 `SELECT COUNT(*)`，**不是** `imports` 累加。见《技术方案-V1.md》§4.2。

## 10. 验收清单

**结构**

- [ ] 头部只有标题 + 一个切换按钮
- [ ] 底部两个 tab（行程 / 地图）
- [ ] 卡片间距 12，列表行间距 8，左右边距 16

**卡片视图**

- [ ] 封面区高 80，主图:副图 = 1.7:1，三图之间有 2dp 间隙
- [ ] 三张图都是裁切填充，没有拉伸变形
- [ ] 行程名、张数、红点、`+N` 在一行内对齐
- [ ] 手记行可点，跳到详情；卡片其它位置跳到地图
- [ ] 没有天气数据时，天气条整体隐藏（不留空行）

**列表视图**

- [ ] 缩略图 60×60，圆角 8
- [ ] 三行文字依次是：名称+张数 / 日期+天数 / 手记首行
- [ ] 没有手记时显示灰字「还没写手记」
- [ ] 整行只有一个跳转（地图），手记行不单独响应

**切换**

- [ ] 按钮图标显示的是"目标视图"，不是当前视图
- [ ] 切换后回到列表顶部
- [ ] 杀掉 App 重开，保持上次的视图
- [ ] 切换动画总时长约 420ms，逐条淡入有节奏感
- [ ] 系统开启"减少动态效果"时无动画
- [ ] 快速连点 5 次不会出现闪烁或残影

**数据**

- [ ] 张数来自 `COUNT(*)`，重复导入不会翻倍
- [ ] 三张封面优先取用户设过的，不足时重复补，不留空
- [ ] 空列表有居中空态，不是一片黑

## 11. 两个可以商量的点

1. **整卡点击进地图**，而不是进详情。
   好处：看位置是第一诉求，少一次转场。
   风险：新用户可能以为"点进去就是详情"。
   → 如果后续数据显示"卡片点击后马上返回"的比例高，改成进详情。

2. **列表视图不显示天气**。
   一行 76dp 塞三行文字已经是上限，天气图标会挤掉手记。
   → 如果用户反馈"想快速看天气"，可以改成点击行展开。
