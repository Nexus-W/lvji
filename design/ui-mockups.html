TripNest · UI Design v1

旅影 TripNest ／ 三套界面方案

定位：把安卓手机 + 大疆 Action 5 Pro 的几千张素材，自动归组成一次次行程，在地图上看见自己走过的地方。
前提：手机端为主、电脑端为辅、纯本地、素材主要躺在手机相册里。

值得抄的三点

  • 照片直接当点位：不用水滴针，用缩略图本身做 marker，一眼就知道"这里拍了什么"，比任何图标都直观。
  • 深色地图 + 一个高饱和强调色：照片在暗底上特别跳，视觉质感一下就上来了。
  • 顶部 KPI 大数字（13528.92 公里）：情绪价值极高，是这类产品最容易被截图分享的部分。

不能照抄的三点

  • "共 301486 个足迹点"是反面教材：几千个点位全铺上去只会糊成一片噪点。我们几千张照片必须做聚合，缩小看城市气泡，放大才裂开。
  • 地图做首页，没有"整理"的抓手：用户真正要干的是"把几千张归好组"，地图是结果不是入口。纯地图首页会让人不知道从哪下手。
  • 它回避了最难的问题：照片没坐标怎么办、多设备时间对不齐怎么办。这恰恰是我们最大的差异点，界面必须显性化。
方案 A

地图优先

Map-First

把参考图的构图做到极致：地图整屏铺满，底部横滑行程卡。适合"看回忆"的场景，视觉冲击最强。 但它把整理动作藏起来了，适合作为第二个 tab而不是首页。

方案 D

电脑端工作台

Desktop Archive

你把电脑端定位成"以后归档用"，所以它不该是手机端的放大版，而应该是更重的操作台：批量导入整张 SD 卡、跨行程合并、批量去重清理、导出归档目录结构。

电脑端的差异化：不做"另一个看图工具"，只做手机端做不了的三件事 —— 整卡批量导入、跨行程批量合并/去重、导出成规范的本地归档目录（`2026/10-云南大理丽江/03-洱海环湖/`）。这样两端不会互相抢活。

我的建议

  • 主结构选 C：地图 × 时间轴联动，信息密度和惊喜感平衡得最好，也是唯一把"整理"和"欣赏"放在同一屏的方案。
  • 把 A 的地图页单独抽出来当第二个 tab：全屏沉浸模式，用于分享截图和"我就想看看"的时刻。两者不冲突，可以共存。
  • B 的行程卡片样式直接复用到 C 的"行程"tab 里，作为列表视图。
  • D 只做三件事：批量导入、批量整理、导出归档。不要试图在电脑端重做一遍看图体验。
配色：深色为主，照片在暗底上更跳 圆角：卡片 14-15px，按钮 11px 字体：系统字 + 等宽数字 地图底图：腾讯位置服务（合规）
